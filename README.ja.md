# **重要**
`v1.11.1`を最後にメンテナンスを停止しましたが、[メインプロジェクト](https://github.com/zero-plusplus/autohotkey-devtools)に影響を与えない程度の小さいパッチを提供することにしました。手間がかからなければ`v2.0.0`で追加予定だった一部機能を移植することもあるかもしれません。ただし、今後もパッチを継続するかどうかは決めておらず今回が最後のパッチになる可能性があります。

[Issues](https://github.com/zero-plusplus/vscode-autohotkey-debug/issues)は受け付けますが必ずしも修正されるわけではありません。返信はトラブルがなければ遅くとも次の日までには対応するようにしています。

> **ヒント:** Issuesでは英語を使うことを推奨しています。[DeepL](https://www.deepl.com/ja/translator)などの翻訳機で十分です。どうしても意図を伝えるのが難しい場合は日本語を並記してください。

## ライセンスの変更について

> **注意: `v1.11.1`より拡張機能の`ソースコード`に対するライセンスが変更されましたが、利用者(エンドユーザ)には影響はありません。これまで通り使えます。**

現在のライセンスではエンドユーザ以外の利用を禁止しており、私のソースコードを他のプロジェクトに含むことを完全に禁止しています。その他、拡張機能パックに含むなどの間接的な影響を与えるような行為もご遠慮ください。これらは私の拡張機能の価値を維持するとともに不要な競合問題を発生させないためのものです。

私の拡張機能が競合せず連携可能なのはマーケットプレイス上で完全に独立したソースコードを持っているからです。しかし、第三者がソースコードを取り込んだ上でマーケットプレイス上にアップロードした場合、組み合わせによっては1つのVSCode上に同一のデバッガアダプタが複数インストールされる状況が生まれます。それによって競合問題が発生すれば、私の拡張機能の信頼性を下げることになるでしょう。

また、ソースコードを取り込むということは私の拡張機能をインストールしなくてもその機能を使えるようにするということです。それは私の拡張機能を成長させるという目的を結果的に妨害することになります。

極端なことを言えばAutoHotkeyをサポートするすべての拡張機能が私のソースコードを取り込んだ場合、連携前提の私の拡張機能は競合問題を発生させるだけの存在になってしまいます。こうなると無価値よりも価値が低く、マーケットプレイス上に存在するだけで迷惑であるため削除せざるを得なくなります。

もちろん、これらは悪影響が発生することを示すための極端な例であり、実際にはそのようなことは起こらないだろうことは理解しています。

上記の問題は実際にソースコードを取り込むことを[提案](https://github.com/zero-plusplus/vscode-autohotkey-debug/discussions/332)されたことで表面化しました。この提案自体はMITライセンスとしてまったく問題はないため、最終的にMITライセンスは私の活動に適していないと判断し、ライセンスを変更することを決めました。このとき、私のライセンスに対する無知、無理解のために多くの迷惑をかけてしまったことをここで謝罪します。また、私のわがままを受け入れてくれたことに感謝します。

ライセンスを変更した後に私がメンテナンスを継続せずに停止することを決めたのは`v1.11.0`までは実質的にMITライセンスであり、上記の問題を根本的に解決することができないからです。

私は拡張機能を成長させるために多くの独自機能を追加し、それによって得たエンドユーザからフィードバックを受けることでより洗練された機能を追加してきました。優れたツールを作るうえでこのサイクルを重要視しているため、それを破壊しかねない問題を抱えながらメンテナンスを継続することはできません。

個人的な事情によりメンテナンスを再開しましたが、最小限のパッチだけに限定しているのはこのためです。

最後に、私のプロジェクトはすべて公開されただけの個人的なツールであり、1人で開発しています。個人的な目標を達成するために意図してそうしているため、協力に関する提案を受け入れることはできません。

上記で説明した通り私が重要視し、かつ受け入れるのはエンドユーザによるフィードバックだけです。

繰り返しますが、ライセンスの変更は開発上の都合であり、エンドユーザには全く関係ありません。

以上です。ここまで読んでいただいてありがとうございました。
